# [NFR-03] 断网后重试不产生重复申请，查询结果保持一致

## 编号

NFR-03

## 用户故事

作为提交报名申请的参与者，我想在网络异常后安全重试并查询真实处理结果，以便不会重复报名、重复占用名额或误以为申请已确认。

## 验收标准

- Given 同一申请已保存但成功响应丢失，When 用户恢复联网后重复提交同一请求，Then 返回原申请记录及当前状态，不新增申请，也不重复占用名额或发送同一申请通知。
- Given 同一申请在断网前尚未保存，When 用户恢复联网后重试并提交成功，Then 只创建一条有效申请，随后可查询到该记录。
- Given 同一用户对同一活动的同一次申请连续或并发提交多次，When 所有请求处理完成，Then 该次申请最多有一条有效记录，活动名额变化与这条申请的业务状态一致。
- Given 原申请已被审批、取消或退出，When 旧请求被重试，Then 不恢复旧状态、不覆盖后续处理；显示当前有效状态。
- Given 网络仍不可用，When 无法确认服务器是否保存申请，Then 显示“结果待确认/暂时无法查询”，不显示确定失败、已报名成功或已确认参加。
- Given 用户在另一设备查询同一申请，When 已恢复联网且查询成功，Then 申请详情与活动名单使用同一最新业务结果，不能一处已退出而另一处仍展示本次查询为已确认。

## 证据强度

弱（团队技术假设）：业务一致性目标由团队推导，未取得重复报名事故的真人证据；应打“假设”标签并技术评审。

## 干系人

参与者 / 发起者（组织者）

## 优先级

P0 —— 建议 P0：报名和名额可信的基础约束，删掉后一次重试可能产生重复申请或错误名额；本优先级为成员 D 提案，待组内确认。

## 待决问题

1. 同一次请求的识别、有效期与不同设备重复报名如何统一，由技术设计确定；验收先固定同用户、同活动、同次意图。
2. 退出后主动重新申请是新意图，应按 US-08/US-09 规则允许或拒绝，不能永久被旧请求去重阻止。
3. 这里的并发重试只验证一致性，不新增吞吐量或延迟承诺；负载指标仍归 NFR-01。
