# \[US-20] 临时起意时找到同校、同一时段的活动意向

> 负责人：成员 B（龚滢蓉）；建议标签：`story`、`P2`、`area-match`、`needs-review`。

## 编号

US-20

## 用户故事

作为临时起意的学生，我想看到此刻同校有哪些人主动发布了同类活动的参与意向，以便在不提前很久约定的情况下，找到可能一起参加的人。

## 验收标准

团队拟议口径：“此刻”指当前时间落在发布者主动填写的有效时段内，且与查询者本次可参与时段有交集。只展示仍有效、允许被该查询者浏览的意向；在线不等于有空，不读取所有同校学生的实时状态。时间窗口与入口方案尚待评审。

- Given 我选择活动类型和本次可参与时段，When 我查看临时找伴结果，Then 只列出同校、同类、当前仍在有效期且与所选时段有交集的公开意向，并显示活动类型、有效时段、手动填写的集合地点及当前招募状态。
- Given 一条意向来自其他学校、与我所选时段无交集，或仅为明天生效的活动，When 我查看“此刻”的结果，Then 该意向不进入本次结果；普通的未来活动仍由常规浏览功能处理。
- Given 另一位同校用户只是在线，未主动发布临时找伴意向，When 我查询同类活动，Then 系统不将其显示为“此刻可参加”的对象。
- Given 某条意向已到有效期结束时刻、已被发布者撤回或已按 US-22 停止普通招募，When 我刷新结果，Then 它不再作为可直接报名的临时找伴结果出现；从旧入口打开时能看到失效或满员说明，不误报报名成功。
- Given 当前没有符合条件的有效意向，When 我完成查询，Then 明确显示“暂无符合条件的临时找伴信息”，并允许修改时段或活动类型，不显示虚构对象或承诺一定匹配成功。
- Given 我未开启或拒绝设备定位权限，When 我使用临时找伴入口，Then 仍能通过同校信息、手动选择时段和地点完成查询，不要求精确定位或持续位置共享。
- Given 我看中一条仍有效的意向，When 我提交参与申请，Then 进入现有报名与确认流程并显示处理结果，不因为时间紧或双方同时在线而跳过确认、直接计为已约好。

## 干系人

参与者 / 发起者。

## 优先级

P2 —— 理由：场景有线索，但真实使用规模、等待意愿与替代渠道优势尚未验证，应在基础发布、报名和状态链路之后评估。删掉本条，临时起意者只能逐条筛普通活动、联系熟人或现场询问。

## 待决问题

1. 是否按本稿的“当前有效 + 时段有交集”定义“此刻”？有效期由发布者填写还是给出默认值，需用场景验证，当前不擅定“30 分钟内必约到”等指标。
2. 临时意向是否直接复用 US-02 的活动记录和字段？建议复用，避免生成独立的报名、确认与失效规则；与 US-22 的截止时间保持一致。
3. 先验证哪些同校场景确实需要临时入口，以及用户愿意等待多久、填写多少信息。只做同校与手动时段/地点，不扩展到自动定位或持续位置共享。
