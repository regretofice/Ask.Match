# \[US-05] 一次看到大家的可用时段，减少逐个协调

>
> 负责人：成员 B（龚滢蓉）；建议标签：`story`、`P0`、`area-time`、`ev-strong`、`needs-review`。

## 编号

US-05

## 用户故事

作为发起者，我想一次看到大家的可用时段，以便找到共同可行的活动时间，减少来回逐个询问。

## 验收标准

以下以“发起者提供候选时段，参与者填写能否参加”作为团队拟议方案。

- Given 发起者已列出带日期、开始时间和结束时间的候选时段，When 参与者选择一个或多个可参加时段并保存，Then 再次打开时能看到自己的最新选择；所有时段都不能参加时，可以明确提交“均不可参加”。
- Given 本次征询对象为甲、乙、丙，甲乙已提交、丙尚未提交，When 发起者查看汇总，Then 能同时看到各候选时段的可参加人数及人员、已提交人数 2/3，以及丙“未填写”；不能将丙计入可参加或不可参加人数。
- Given 三人均已提交且都选择同一候选时段，When 发起者查看汇总，Then 该时段标为“三人均可参加”；只收到部分人的选择时，只能标为“已填写者均可参加”，不能表示全员可行。
- Given 所有人均已提交但没有一个候选时段得到全员选择，When 发起者查看汇总，Then 明确显示“暂无全员共同可用时段”，并保留各时段的选择情况供继续协商，不自动替任何人作参加承诺。
- Given 参与者修改了自己的选择并保存成功，When 发起者重新打开或刷新汇总，Then 人数和人员按最新选择更新，同一人在同一时段只计算一次。
- Given 发起者已根据汇总选定活动时间，When 保存最终安排，Then 活动详情显示选定时间；填写“有空”不自动等于报名或确认参加。若修改的是已发布的时间，后续通知与重新确认分别衔接 US-06、US-08。

## 优先级

P0 —— 理由：共同时间无法确定会直接阻碍活动安排，多人逐个询问存在反复协调成本。删掉本条，发起者仍需自行收集、比对每个人的空闲时间。

## 待决问题

1. 是否采用候选时段选择方案，还是允许自由填写时间区间？本稿按前者验收，不涉及读取课表或个人日历。
2. 征询对象包括哪些人，谁可查看逐人选择？本稿仅要求发起者可查看参与本次征询者的结果，不向无关用户公开个人安排。
3. 新增候选时段或变更征询对象后，如何提示补填？未填写的部分应继续保留为未知，不能自动视为同意。
