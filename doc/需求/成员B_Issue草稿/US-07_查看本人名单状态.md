# \[US-07] 随时查看自己是否仍在参加名单中

>
> 负责人：成员 B（龚滢蓉）；建议标签：`story`、`P1`、`area-time`、`ev-strong`、`needs-review`。

## 编号

US-07

## 用户故事

作为参与者，我想随时查看自己是否仍在活动参加名单中及当前状态，以便知道是否需要按这次活动安排行程。

## 验收标准

本条负责查询自己的名单归属与状态，状态含义及迁移沿用 US-08、US-09、US-10、US-12 的评审结果。以下状态名称与现有清单对齐，展示方式为团队拟议方案。

- Given 我已提交申请且发起者尚未处理，当前不处于候补或待重新确认状态，When 我打开活动详情查看本人状态，Then 明确显示“已提交／尚未确认”，并说明当前不在已确认参加名单中，不能只用“已报名”暗示已经约好。
- Given 我已经进入活动的已确认名单且尚未退出，When 我打开活动详情，Then 能直接看到“本人在已确认参加名单中”及当前活动时间地点，无需通过群聊或其他人的答复推测。
- Given 我的当前状态是候补，When 我查看本人状态，Then 明确显示“候补，尚未确认参加”，不计作已确认参加者；获得空位并按 US-10 完成确认后，重新查看时才显示相应最新状态。
- Given 我已按 US-12 成功退出活动，When 我再次打开详情或历史报名入口，Then 本人状态显示“已退出”，不再显示仍在已确认参加名单中，也不删除这条退出结果。
- Given 活动安排变更后，US-08 已将我置为“待重新确认”，When 我查看本人状态，Then 显示“待重新确认”和最新安排，不能继续展示旧的“已确认”；是否保留名额依照 US-08/US-09 的统一规则。
- Given 当前网络异常，系统无法取得最新名单，When 我尝试刷新本人状态，Then 显示“暂时无法获取最新状态”；若保留上次状态，须标明它不是本次查询结果，不因加载失败显示“不在名单中”。

## 优先级

P1 —— 理由：需要在报名、候补、退出等状态确定后统一呈现查询结果，帮助参与者判断还要不要参加。删掉本条，参与者可能仍要翻看历史通知或再次询问发起者；基础状态定义则依赖 P0 的 US-08。

## 待决问题

1. 与 US-08 的分工建议：US-08 定义“何时算确认及如何迁移”，US-07 负责“从哪里查询本人当前名单归属并保持一致”。若评审认为两者没有独立用户价值，可并入 US-08；本次仍按分工保留独立草稿。
2. 原追溯矩阵遗漏 US-07。建议关联 UC-02 浏览与申请、UC-03 审批与名额管理，待组长确认后再回填，不声称现有矩阵已包含。
3. “已接受”是否等同“已确认”、待重新确认时是否保留名额，现有 US-08 尚未完全明确。本条不替组长决定，也不将已付款、参与讨论或已到场自动视为平台确认。
4. 查看其他参加者姓名、关系线或联系方式不属于本条，按 US-18、US-19 与 NFR-02 的可见范围执行。
