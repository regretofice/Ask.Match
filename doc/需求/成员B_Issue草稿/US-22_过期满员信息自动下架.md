# \[US-22] 自动下架过期或满员的招募信息，减少人工维护

>
> 从 负责人：成员 B（龚滢蓉）；建议标签：`story`、`P1`、`area-ops`、`needs-review`。

## 编号

US-22

## 用户故事

作为运营管理员，我想让系统自动下架已过期或人数已满的搭子招募信息，以便不必逐条手动处理，并减少同学对失效信息发起无效申请。

## 验收标准

- “过期”按招募截止时间判定，截止时间不得晚于活动开始时间；未单独填写时暂取活动开始时间。当前时间达到截止时间（含相等）即停止招募，不能等到活动结束才处理。
- “满员”按 US-08/US-09 统一规则下已占用的正式名额达到人数上限判定；申请数、浏览数和候补人数不直接当作正式占位数。是否临时保留名额由相关故事统一决定。
- “下架”指退出可直接报名的公开招募列表、关闭普通报名入口；保留活动详情、成员、历史和候补记录，不等于取消活动或删除数据。普通浏览与 US-20 临时找伴采用同一有效性口径。
- 满员后出现空位时，先按 US-09/US-10 处理已有候补；本稿暂不自动恢复公开招募，待发起者确认重新招募，且必须仍未过期、仍有可用名额并已完成候补优先处理。恢复策略待评审。
- Given 活动招募截止为 17:30、开始为 18:00，且 17:29 仍有空位，When 当前时间到达 17:30 后用户重新查询公开招募列表，Then 该活动不再列为可直接报名，并标记“已过期”；无需管理员逐条操作。
- Given 活动未过期且人数上限为 5，When 按统一规则占用的正式名额从 4 变为 5，Then 后续列表查询不再将它列为可直接报名，详情显示“已满员”，普通报名关闭。
- Given 活动上限为 5、正式占位为 4，另有未占位的待审核申请或候补，When 系统判断是否满员，Then 不仅因为申请或候补总数超过 5 就判为满员；占位与并发一致性按 UC-03、NFR-01 处理。
- Given 用户已打开尚有空位的旧页面，期间活动已过期或满员，When 用户提交普通报名，Then 系统按提交时的最新状态阻止无效报名，显示具体原因，不新增正式名额；满员且仍在允许候补时段内时，按 US-09 提供候补处理。
- Given 活动因过期或满员下架但并未取消，When 发起者、已报名参与者或已有候补者从自己的活动记录进入，Then 仍能按权限查看详情及本人状态，已确认名单与已有候补记录不会因为下架消失。
- Given 活动满员且仍允许候补，When 用户从保留的活动详情入口申请候补，Then 按 US-09 处理并明确显示候补结果，不将其算作正式报名；到招募截止时间后，本稿暂关闭新报名及新候补，已有候补是否仍可递补按待决问题统一。
- Given 活动因满员下架后有人退出，When 出现空位，Then 不立即重新向所有人开放普通报名；先处理已有候补。发起者申请恢复公开招募时，只有仍未过期、有可用名额且候补优先处理已完成才允许恢复；任一条件不满足则说明原因并保持下架。
- Given 活动已经过期或已经取消，When 人数减少或发起者尝试按“满员后恢复”重新开放，Then 不能因此自动恢复招募，原状态和已有记录保持可查。

## 证据

- [EV-O01-Q3 / O01 问题三原话](https://github.com/regretofice/Ask.Match/blob/20148e6dd5788386aea3692dd9482981e926d061/doc/调研报告/有问必搭_运营管理员访谈记录.md#L30-L34)：一位拟任运营者希望自动下架过期或人数已满的信息，减少逐条手动处理；同一回答也提出管理后台，后台部分由 US-24 覆盖。

## 证据强度

中（沿用现有清单对运营侧陈述的评级）。O01 明确表达了减轻维护压力的愿望。

## 干系人

运营管理员 / 发起者 / 参与者。

## 优先级

P1 —— 理由：项目采用学生自治运营，管理人力有限，失效招募信息需要可持续的维护方式。删掉本条，管理员或发起者需逐条处理，参与者也更容易接触不能加入的活动；实际维护频率与减负规模仍需试运行验证。

## 待决问题

1. 是否采用独立招募截止时间及“默认取开始时间”的口径？普通报名与候补是否共用截止时间，正式活动“至少提前一天”的候补意见如何与 US-10 协调？本稿暂按同一截止时间关闭新报名和新候补，不代替候补规则决策。
2. 满员信息退出公开招募列表后，候补发现入口放在哪里？本稿保留详情及个人记录入口；是否另设“可候补”活动列表，需要与组长评审，避免下架使候补无法使用。
3. 满员后有空位，采用本稿的发起者确认恢复，还是满足条件后自动恢复？两者都必须尊重候补优先顺序，不能让新申请绕过已有候补者。
4. 待接受、待重新确认或等待候补回应期间是否占位，交由 US-08/US-09/US-10 统一；本条只消费统一占位结果，不自行设定状态机。
5. 招募截止之后已有候补能否继续确认，和下架的处理延迟、失败重试如何验收，需在 UC-09 与相关 NFR 细化；目前不虚构运营方已要求的秒级指标。

## 关联用例

UC-09 信息自动下架（沿用现有追溯矩阵）；名额与候补依赖 UC-03 审批与名额管理。
