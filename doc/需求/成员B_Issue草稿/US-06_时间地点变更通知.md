# \[US-06] 时间或地点变更后收到明确通知，及时调整行程

>
> 负责人：成员 B（龚滢蓉）；建议标签：`story`、`P0`、`area-time`、`ev-strong`、`needs-review`。

## 编号

US-06

## 用户故事

作为参与者，我想在活动时间或地点被修改时收到通知，以便按最新安排调整自己的行程。

## 验收标准

本条必须通知的对象是：本次变更前已确认且尚未退出的参与者，以及因先前变更处于“待重新确认”且尚未退出的参与者。不能因本次改期使其状态变为“待重新确认”而漏发；待审核者与候补者是否同样通知，列入待决问题。通知内容与处理方式为团队拟议规则。

- Given 活动原定周六 18:00 在 A 门集合且我已确认参加，When 发起者将时间改为 17:00 并保存成功，Then 我能在站内通知中看到活动名称、原时间 18:00、新时间 17:00、仍为 A 门的集合地点以及变更发生时间。
- Given 我已确认参加且活动时间不变，When 发起者将集合地点由 A 门改为 B 门并保存成功，Then 我收到的通知明确列出原地点 A 门、新地点 B 门和当前活动时间，不只显示“活动已更新”。
- Given 发起者在一次保存中同时修改时间和地点，When 变更成功，Then 面向同一参与者生成一条完整的本次变更通知，包含两项变更前后内容，不遗漏其中一项。
- Given 时间或地点已连续修改两次，When 我从第一次变更的旧通知进入详情，Then 详情展示当前最新时间地点，并提示存在后续变更，不把第一次通知中的安排当成当前安排。
- Given 我曾确认参加，因第一次变更处于“待重新确认”且尚未退出，When 发起者再次修改时间或地点并保存成功，Then 我仍能收到本次变更通知，不能因当前不叫“已确认”而被遗漏。
- Given 我暂时离线而活动安排已变更，When 我恢复联网并打开通知列表，Then 能查看离线期间产生的变更通知并进入最新详情；通知已生成或已被打开，都不能直接将我标为已重新确认参加。
- Given 发起者只是打开编辑页后取消，或保存后的时间地点与原安排相同，When 我查看通知，Then 不出现这次并未实际发生的时间地点变更通知。

对“活动 2 小时内开始且时间被修改”的通知渠道、1 分钟时限和失败重试，衔接现有 NFR-04 草案，本条不另设相冲突的数值指标。

## 证据强度

强。三位受访者描述了变更或协调经历。

## 干系人

参与者 / 发起者。

## 优先级

P0 —— 理由：时间地点直接影响参与者能否正确到场，依赖发起者逐人转告容易增加协调负担。删掉本条，参与者仍需主动追问安排是否变化。

## 待决问题

1. US-14 已包含“取消或改期通知”，与本条的改期部分重复。建议改期共用同一次变更通知及验收，活动取消由 US-14 覆盖；是否调整故事边界，由成员 C 与组长评审，避免重复实现、重复通知。
2. 待审核申请者、候补者是否也属于通知对象？本稿已将变更前已确认者及因先前变更处于待重新确认且尚未退出者纳入必须通知范围。
3. 时间或地点变化后的重新确认条件由 US-08 定义；通知可达、已读或送达含义与 US-15、NFR-04 对齐，不能把“打开通知”当成“同意新安排”。
